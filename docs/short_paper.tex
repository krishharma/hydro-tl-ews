\section{Introduction}

For most rivers, there are no long records of how much water flows through
them. When only one or two years of data are available for a gauge, machine
learning will memorize the data for that river instead of learning about the
relationship between the river's flow and different weather patterns. Transfer
learning can be used to solve this problem:
\begin{enumerate}
  \item Train a model on \textbf{donor basins} with long records outside the
        watershed of the river to be measured.
  \item Apply that model to the \textbf{target basin}, even if it has a short
        record of its flow.
  \item \textbf{Fine-tune} the model with a few years of data from the target
        river.
\end{enumerate}

The model forecasts daily streamflow and the likelihood of flow crossing
drought or flood thresholds over the coming 1, 3, or 7 days. The code is open
source at \repo, with setup in
\href{https://github.com/krishharma/hydro-tl-ews/blob/main/data/README.md}{data/README.md},
settings in
\href{https://github.com/krishharma/hydro-tl-ews/tree/main/configs}{configs/},
and run instructions in
\href{https://github.com/krishharma/hydro-tl-ews/blob/main/docs/RUNNING.md}{docs/RUNNING.md}.

Although a full continental CAMELS-US run was put off because of compute
limits, a Midwest laptop study was finished using the supervisor's advice to
optimize for what this PC can handle. The target was Lick Creek near Perry, MO
(USGS~05507600), with 17 similar Midwest donor basins. Results and a check
against the project objectives are in Section~\ref{sec:results}. A later
sensitivity pass tried a smaller donor pool, mean daily temperature, and
multi-seed averaging (Section~\ref{sec:opt}); it did not beat the 17-donor
benchmark. The original Merced / multi-regime plan is still in the repository
configs; basins for that larger study are listed in Table~\ref{tab:basins}.

\section{Data}

\subsection{CAMELS-US}

All real experiments use \textbf{CAMELS-US}, a dataset that includes
${\sim}$671 gauges located throughout the contiguous United States. At each
gauge, there are daily measurements of precipitation, temperature (from
Daymet), streamflow (from USGS), and various attributes of the watershed
itself. The majority of the gauges are used as \textbf{donors} (training
data), while \textbf{targets} are held out for testing
(Figure~\ref{fig:camels}). The CAMELS dataset is not bundled with this
repository, but instructions for downloading it are in
\href{https://github.com/krishharma/hydro-tl-ews/blob/main/data/README.md}{data/README.md}.

\subsection{Model inputs and output}

\textbf{Daily weather} (six variables): precipitation, maximum and minimum
temperature, shortwave radiation, vapor pressure, and day length.

\textbf{Watershed properties} (27 static attributes): topography, climate, land
cover, soils, and geology. These attributes describe the watershed that is being
simulated by the model. The same weather patterns can lead to different
streamflow in different watersheds due to these different watershed properties.

\textbf{Prediction target:} daily streamflow in mm/day, derived from USGS
streamflow measurements in cfs by dividing by watershed area.
Table~\ref{tab:inputs} summarizes all inputs.

\section{Methodology}

The workflow consists of four main stages: training the model on a collection of
regional basins, adapting the model to the particular basin of interest,
evaluating the model on that basin using walk-forward analysis, and
early-warning scoring.

\subsection{Regional model (EA-LSTM)}

The model that is used in this project is an \textbf{Entity-Aware LSTM}
(EA-LSTM). For the EA-LSTM, the properties of the watershed control the
\textbf{input gate}, while the weather and memory drive the remaining gates of
the LSTM. Thus, each EA-LSTM can be trained to represent multiple basins. Each
day, the EA-LSTM is provided with the weather of the previous lookback window
(365 days in the full configs; \textbf{90 days} in the Midwest laptop run), and
it can use this information to forecast the streamflow that will occur that day.
During pre-training, the EA-LSTM is exposed to streamflow data from multiple
different basins and minimizes its error in predicting discharge from each of
those basins.

\subsection{Transfer to the target basin}

After pre-training, four adaptation strategies are compared:
\begin{itemize}
  \item \textbf{Zero-shot} --- no local training; tests the model's knowledge
        of the regional corpus alone.
  \item \textbf{Approach A} --- trains only the output head of the EA-LSTM while
        leaving the LSTM portion intact (safest with limited local data).
  \item \textbf{Approach B} --- trains the output head and the upper LSTM layers
        at a reduced learning rate (more adaptation, higher overfitting risk).
  \item \textbf{Local baseline} --- trains a new EA-LSTM from scratch on the
        warmup data only.
\end{itemize}

\subsection{Walk-forward evaluation}

Random splits of the streamflow time series into train and test data can lead to
data leakage of temporal structure because the flow on one day is similar to the
flow on the previous day. Shuffled splits can therefore make models appear to
perform better than they do in reality. This project uses \textbf{walk-forward
evaluation} to approximate deployment with limited startup data:
\begin{enumerate}
  \item Start with warmup data only.
  \item Forecast the next block of days and score against observations.
  \item Every 90 days, retrain on all discharge from the warmup start forward.
  \item Apply online bias correction.
  \item Advance through 2011--2014 without using future observations before
        forecasting them.
\end{enumerate}

This evaluation method is more rigorous than a single random split of the data
into train and test sets and provides a more honest estimate of performance when
only a short local record exists at startup.

\subsection{Early warnings and metrics}

A post-processing layer translates streamflow forecasts to Q5, Q95, and Q99
crossing probabilities at 1-, 3-, and 7-day leads. Warning skill scores are
based on AUC, F1@0.5, and the Brier score. These warnings are based on
hindcasted flow forecasts, not a separate multi-day weather forecast. Streamflow
forecast skill is scored using NSE, KGE, and PBIAS.

\section{Results and observations}
\label{sec:results}

\subsection{What was actually run}

The original project brief asked for pretraining on all ${\sim}$671 CAMELS-US
basins and then transferring to a snowmelt-dominated Sierra/Rockies target.
After the supervisor suggested focusing on what could be finished on this PC,
the completed experiment used Midwest data only:

\begin{itemize}
  \item \textbf{Hardware:} Apple M4 laptop, Apple Silicon MPS, ${\sim}$16\,GB RAM.
  \item \textbf{Data extract:} CAMELS attributes for all gauges, but only Daymet
        forcings and USGS streamflow for HUC folders \texttt{04}, \texttt{05},
        \texttt{07}, and \texttt{10} (${\sim}$200\,MB of time series, not the full
        ${\sim}$14\,GB continental unpack).
  \item \textbf{Geographic pool:} 163 CAMELS basins inside the Midwest box
        $[36.5^\circ\mathrm{N},\,49.5^\circ\mathrm{N}]\times
        [-104^\circ\mathrm{W},\,-80.5^\circ\mathrm{W}]$.
  \item \textbf{Donors:} the 17 basins most similar to the target in static
        attributes, after a 50\,km exclusion buffer and dropping gauges that
        were missing local files.
  \item \textbf{Target:} USGS \textbf{05507600} (Lick Creek near Perry, MO;
        continental plains; $\mathrm{frac\_snow}\approx 0.07$).
  \item \textbf{Model:} EA-LSTM, hidden size \textbf{128}, lookback
        \textbf{90} days, dropout 0.4.
  \item \textbf{Pretrain:} 10 epochs, batch size 128, NSE loss; validation
        NSE-loss fell from 0.94 (epoch~1) to 0.78 (epoch~10).
  \item \textbf{Adaptation compared:} zero-shot; Approach~A (head-only fine-tune
        on the 2-year warmup); local-from-scratch baseline. Approach~B was not
        run here.
  \item \textbf{Walk-forward:} 2011--2014, refit every 90 days
        (\textbf{17 refits}), \texttt{refit\_train\_start=2009-01-01} so refits
        stay honest to scarce local data, online bias correction, 1\,461 scored
        days.
  \item \textbf{SHAP:} GradientExplainer after walk-forward (200 background /
        100 sample sequences); importance written to
        \texttt{results/midwest\_mini/shap\_global\_importance.csv}.
  \item \textbf{Command:}
        \texttt{python scripts/run\_midwest\_mini.py}
        (configs in \texttt{configs/midwest\_mini/}).
  \item \textbf{Artifacts:} \texttt{results/midwest\_mini/summary.json} plus the
        metric, prediction, warning, and SHAP files beside it.
\end{itemize}

\subsection{Continuous streamflow skill}

Table~\ref{tab:midwest_metrics} shows NSE, KGE, and PBIAS on the shared
2011--2014 window ($n=1461$ days). Transfer from similar Midwest stations beats
training from scratch on the two-year warmup alone. Fine-tuning also raises KGE
and nearly clears the large negative volume bias seen in zero-shot. Walk-forward
is the strongest continuous result here, which fits a model that is refit as
local observations arrive.

hydrograph. What still matters for this project is the ranking:
\textbf{transfer $\gg$ local}.

\subsection{Early-warning skill}

Thresholds from the long local record were Q5~$=0.0$\,mm/d (near-zero /
intermittent low flow at this gauge), Q95~$=3.26$\,mm/d, and Q99~$=16.91$\,mm/d.
Table~\ref{tab:midwest_ews} summarizes walk-forward warning scores. Flood and
drought discrimination (AUC) is strong to good, especially at short leads. F1 at
probability 0.5 stays modest, and Brier scores get worse at 3- and 7-day leads.
That pattern fits warnings built from a hindcasted daily flow model rather than
a separate multi-day weather forecast. Q99 F1 is undefined because too few
events cross the 0.5 probability cutoff---a rarity issue, not a broken pipeline.

\subsection{SHAP interpretation}

SHAP was also run after walk-forward on the fine-tuned Midwest model.
GradientExplainer used 200 background sequences and 100 samples from the target
basin history. The highest mean absolute SHAP values were all weather variables.
Precipitation ranked first, then vapor pressure, shortwave radiation, day
length, minimum temperature, and maximum temperature
(Table~\ref{tab:midwest_shap}). Static watershed attributes had mean absolute
SHAP of zero in this single-basin setup. That does not mean the model ignores
catchment properties; those inputs are fixed for one gauge, so within-basin
attributions naturally point at the weather that changes day to day. For this
rainfall-runoff plains basin, precip leading the ranking is hydrologically
sensible.

\subsection{Objective-by-objective assessment}

Against the original research objectives, under the Midwest scope the supervisor
approved:

\begin{enumerate}
  \item \textbf{Regional pre-training pipeline --- met (optimized).}
        An EA-LSTM was pretrained on real CAMELS Midwest donors. The full
        671-basin continental pretrain was skipped on purpose.
  \item \textbf{Fine-tuning for a data-scarce target --- met.}
        Approach~A (LSTM frozen; head trained on ${\sim}$2 years of local $Q$)
        finished on 05507600. The brief first preferred a snowmelt target; the
        supervisor chose Midwest plains while keeping the same scarce-data
        protocol.
  \item \textbf{Quantify the value of transfer learning --- met.}
        Fine-tuned transfer beat local-from-scratch by a wide margin
        (NSE 0.160 vs.\ 0.009; KGE 0.112 vs.\ $-0.351$) and improved bias versus
        zero-shot (PBIAS $+4\%$ vs.\ $-37\%$).
  \item \textbf{Walk-forward validation --- met.}
        Rolling-origin testing with honest \texttt{refit\_train\_start},
        17 refits, and online bias correction gave the best continuous scores
        in this study (NSE 0.179, KGE 0.161).
  \item \textbf{Probabilistic early warning --- partially met.}
        AUC, F1, and Brier were produced at leads 1/3/7 for Q5, Q95, and Q99.
        Discrimination is strong; decision metrics (F1, longer-lead Brier) are
        weaker and should be read carefully.
  \item \textbf{Explainable AI (SHAP) --- met.}
        GradientExplainer attributions were computed on the fine-tuned model.
        Weather drivers dominate; precip is the top feature, which fits a
        plains rainfall-runoff basin.
\end{enumerate}

\subsection{Verdict}

\textbf{Yes --- under the optimized Midwest scope, all six research objectives
are addressed.} The run shows regional EA-LSTM pretraining on a laptop-sized
real CAMELS extract; with only about two years of local data, transfer learning
beats training from scratch; walk-forward gives an honest ops-style skill
estimate; flood/drought warning scores can be made from the same forecasts; and
SHAP points at weather drivers led by precipitation.

This paper does \emph{not} claim continental CAMELS performance, snowmelt-regime
transfer, or a seven-basin multi-regime study. Those stay as future work if more
compute and disk become available. A longer narrative is in
\href{https://github.com/krishharma/hydro-tl-ews/blob/main/docs/OBSERVATIONS_MIDWEST.md}{docs/OBSERVATIONS\_MIDWEST.md}.

\subsection{Sensitivity to further optimizations}
\label{sec:opt}

After the Midwest pilot, the supervisor suggested a few additional changes that
had shown up in other recent hydrology work. These were tested on the same Lick
Creek target (USGS~05507600).

First, instead of 17 similar Midwest donors, only about eight of the nearest
neighbors were kept (Pool et~al., 2021, \emph{Water Resour.\ Res.}). Asking for
the seven nearest left only five basins after gauges missing from the partial
CAMELS extract were dropped, so later runs asked for the ten nearest and kept
eight with local files. Second, the LSTM forget-gate bias was already set to
$+3.0$ in the baseline, so that change did not need to be added. Third, daily
minimum and maximum temperature were replaced with a single daily mean
temperature. Fourth, the same setup was trained with three random seeds (42,
123, and 456), and the daily streamflow predictions were averaged before
scoring.

None of these changes beat the original 17-donor Midwest pilot on continuous
skill (Table~\ref{tab:opt_metrics}). For 2011--2014, walk-forward NSE was 0.179
for the baseline, 0.138 when donors were pruned but Tmin/Tmax were kept, and
0.165 for the combined mean-temperature plus three-seed ensemble with eight
donors. Fine-tune NSE followed the same pattern: 0.160, 0.113, and 0.133. In
every setting, transfer learning still beat training from scratch under the
two-year scarce-data protocol.

the runner is
